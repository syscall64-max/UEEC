# Stage 10.9 — initial native benchmark
Run `python3 benchmark.py --rounds 1001 --cpu 5 --output results-01` from this directory (choose an allowed CPU with `taskset -pc $$`). Output directory must not exist. Requires Linux x86-64, GCC with static libc, make, Python 3, binutils. No root needed. Repeat with different output names. The benchmark rebuilds stage 10.8 native fixtures and generates an instrumented loader, leaving original source unchanged. Six modes execute the same relocation fixture (result 40); ordinary modes share identical input, fixed/prelinked have additional metadata. Direct and prelinked use identical file bytes. Ten warmup rounds excluded; randomized order with fixed seed. Each observation is a fresh process, warm filesystem cache, not cold disk. Timing is CLOCK_MONOTONIC_RAW from before load_image to just before entry, and entry separately; first-touch page faults may move to entry in direct mode. Python subprocess timing includes process launch, teardown and output collection. Diagnostic printing suppressed inside timed interval, counters retained; scattered copy counter added because original only counted arena copies. Counts are loader-specific, not whole-process syscall totals. No subtracting clock overhead. Paired speedup is median of per-round ratios against monolithic. Results include raw CSV, summary, environment and source hashes. Small fixture only; not representative of large apps. No ELF comparison, perf hardware counters, RSS, or cold-cache measurement yet. Fixed placement reduces ASLR for the image. Do not treat timing as a security-equivalent ELF comparison. Pilot data from sandbox is not physical-machine evidence.

## 10.9.2 — Section size scalability
Run `python3 sweep_size.py --rounds 101 --cpu 5 --output results-size-01` on native Linux x86-64. Eight sizes, six modes, ten warmup rounds per size, randomized mode order within each round. The added bytes extend the existing initialized program data section with a deterministic nonzero pattern; existing code, relocations and imports remain unchanged. The entry does not read the added region. This deliberately measures startup/lazy mapping, not full working-set access. SH32, little endian, host page granularity. Only the benchmark-generated loader changes the file limit from 64 MiB to 128 MiB for both paths; fixed base is 0x300000000000, native x86-64 only. Original loader remains untouched. Load+entry medians are computed per execution; subprocess time includes Python spawning and cleanup. No cold-cache or ELF comparison. All runs require result=40 and expected operation counters; input hashes verified after each size. The sweep deletes regenerated fixture files and the benchmark executable after each completed size, retaining instrumented C source, raw timings, summaries and environment metadata. A failure stops the run. Use a fresh output directory for each repeat. Pilot: 2 measured rounds at 4 KiB, 64 KiB, 1 MiB and 64 MiB (48 executions), not statistical evidence. CPU affinity is optional; use a valid CPU ID.

## 10.9.3 — Relocation scalability (native x86-64)

Run `python3 sweep_reloc.py --rounds 101 --cpu 5 --output results-reloc-01`.
Six counts (1, 10, 100, 1000, 10000, 100000), six modes, 101 measured rounds each, ten warm-up rounds per count; 3636 measured executions. Each round shuffles modes deterministically. The initialized data section is fixed at 800096 bytes; the relocation section grows from 20 to 400016 bytes, so the comparison includes metadata copying/parsing overhead. Uses the existing SECTION_BLOCK_N / 32-bit entry encoding, one block with base zero and ABS64 pointers. All relocated pointers are checked after the timed entry; the subprocess time includes this verification, whereas load and entry times exclude it. Only the first relocated pointer is consumed by the original application. Import count remains four. The experiment-only Python prelinker and instrumented C loader specialize to this synthetic workload; production loader is unchanged. Warm cache, no ELF comparison. Prelink preparation cost is not timed. Pilot: 72 measured executions (2 per mode/count), all successful, not a statistical conclusion. Raw pilot data and instrumented source retained in pilot-reloc. No cross-architecture or sanitizer test claimed for this benchmark.

Six modes, ten warm-up rounds per count, randomized order, 3636 timed executions. Keep raw CSV, summary, environment and instrumented source. The original loader is unchanged; benchmark copy raises object limit to 10000 and uses the existing experimental BLOCK_N/32 ABS64 path with one relocation. Program and library data sections remain 80096 and 40008 bytes respectively. Two libraries, unique named imports, SIMPLE_FLAT data exports with sorted names; import/export metadata grows with count. The four original imports and one relocation are exercised by the program (result 40); all extra pointers and their integer values are verified after the timed entry. Offline prelink uses binary search of sorted flat exports. This is not a general prelink validator, nor an isolated lookup microbenchmark. Warm cache; extra data accesses are outside timed interval but included in subprocess time. Offline preparation time not measured. Pilot: 72/72 timed executions (2 rounds per count); see pilot-import. No physical-machine result or sanitizer claim for this benchmark extension.

## 10.9.5 — Library scalability (native x86-64 Linux)

Run `python3 sweep_library.py --rounds 101 --cpu 5 --output results-library-01`.
The seven configurations contain 1, 2, 4, 8, 16, 32, or 64 internal libraries, all used by 128 unique named imports. The first library contains the two function bodies and original two data symbols; the other 124 data symbols are distributed across all libraries. Total library initialized data is 504 bytes; program initialized data is 80096 bytes; one ABS64 relocation remains. Each library uses SIMPLE_FLAT exports. The benchmark verifies the original result (40), relocation pointer and all 124 additional imported values after timed entry. All six modes use identical logical workloads within each configuration. File size, header/metadata size, page rounding, and per-library export table sizes vary; these are not isolated from node count. Warm cache, 10 warmup rounds, randomized within-round ordering, separate subprocesses. Offline preparation is outside timing. The experiment-only loader is generated from unchanged stage 10.8 source. Native pilot: 84 measured executions passed (2 rounds per configuration), excluding 420 warmup executions. No sanitizer or other architectures tested for this benchmark. Do not interpret the pilot as a stable performance estimate.

## 10.9.7 — file page cache residency

Run `python3 benchmark_cache.py --libraries 64 --rounds 101 --cpu 5 --output results-cache-01` in 10_performance. This uses the combined workload and randomizes all 12 cache/mode pairs in each round (two excluded warmup rounds). Before each execution, cold uses fsync and POSIX_FADV_DONTNEED; warm reads the entire input file. mincore checks zero/full resident pages respectively. Any failure aborts rather than labeling a partially resident file cold/warm. Conditioning is outside all timed intervals. This does not flush disk/controller caches, executable caches, or system-wide caches. Residency is a snapshot immediately before subprocess launch. The unused 64 MiB section remains untouched during timed entry. Requires Linux native x86-64 and sufficient free storage/RAM. No sudo required. Archive only raw.csv, summary.csv, environment.json and loader_bench.c from the output directory. Pilot: 24 measured executions; no sanitizer run.

## 10.9.9 ELF comparison (x86-64 Linux, 4 KiB pages)

Run `python3 benchmark_elf.py --libraries 64 --rounds 101 --cpu 5 --output results-elf-01`.
Four variants: UEEC monolithic, UEEC direct (fixed prelinked), static non-PIE ELF, dynamic PIE ELF with eager binding and generated DSOs. Both ELF variants reuse the exact program/add/sub machine bytes from the UEEC fixture. Both access modes verify result 40, 100,000 relocation destinations and 9,996 additional imported values. Full means one volatile byte read per 4 KiB page of the 64 MiB constant section, not every byte. The measured end-to-end interval includes subprocess launch, GNU time wrapper, verification and exit. RSS and page faults are recorded for the target process. UEEC internal timing is not used for cross-format comparisons. Static ELF resolves links at build time; the dynamic ELF has additional CRT/system relocations and libc dependency. Generated DSOs are external ELF files versus UEEC internal nodes; this is an architectural comparison, not a controlled isolation of file format alone. Cache conditioning includes generated workload files and UEEC loader, excludes system interpreter/libc, GNU time and device cache. Offline generation/linking cost is excluded. The two-repeat container pilot is only a smoke test, not publishable timing evidence. No sanitizer run for this extension. Python asserts must remain enabled.

Archive results with `zip results-elf-01.zip results-elf-01/{raw.csv,summary.csv,environment.json,loader_bench.c,elf_harness.c,elf_payload.S,elf_static-readelf.txt,elf_dynamic-readelf.txt}`. Keep generated binaries locally for reproduction. Builds may require several hundred MiB of free disk space.

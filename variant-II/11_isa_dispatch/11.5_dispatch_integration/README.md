# UEEC Variant II — 11.5 integration
Run `make test` then `make sanitize` from 11_isa_dispatch. Cross compilers and QEMU commands are inherited from 11.4 Fix 1. `make ppc64` in this directory runs just PPC64 (all payload compilers still required).

18 common UEEC files (2 metadata byte orders × 3 section header sizes × 3 payload variants) are generated once per make invocation. Every architecture uses these identical files; SHA-256 is checked before and after each process. Four loading modes give 72 cases per architecture. Each process loads and releases its image three times and calls the entry twice per load. The native code reads shared constant data, reads/writes initialized data and BSS, and returns the computed sum. The second call verifies state persistence; the next load verifies reset. The host checks section addresses, contents and return values. The experimental ABI passes three section pointers directly; this is not a general UEEC entry ABI or relocation implementation. The PPC64 ELFv1 bridge forwards the three pointer arguments while preserving LR and TOC.

Full matrix: 864 cases, 2592 load cycles, 5184 calls. Per-architecture JSON reports and aggregate `build/integration-report.json`; sanitizer run checks x86-64 only (and overwrites its per-architecture report, not the aggregate). No new malformed-file matrix; retain 11.4 for regression rejection tests. No physical hardware verification beyond host, no imports/exports/relocations, no deliberate protection fault tests or independent mapping leak audit. Host-only validation used dummy bytes for nonselected nodes, not included in distribution. Other target assembly/run results remain unverified here.

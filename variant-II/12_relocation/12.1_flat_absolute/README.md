# 12.1 — FLAT absolute data relocation
Based on stage 11.5 and the original 03_reloc FLAT layout. Each node owns a relocation section and an INIT_DATA section containing a target-endian pointer addend (1). The CONSTANT_DATA section is shared. FLAT metadata is file-endian. One couple16, one entry, ABS32 or ABS64 matching the target pointer width. Relocation is applied before final memory protection; the relocation metadata is read directly from the file mapping, not included in the runtime header or resident section list. Native payload dereferences the relocated pointer slot passed as its first argument; the remaining arguments are the existing writable sections. The test ABI is not a final UEEC ABI.

`make test` builds real payloads for all 12 targets; `make sanitize` repeats x86-64 under ASan/UBSan. 18 common files, 4 loading modes, 72 cases per architecture; each case includes 3 loads and 6 calls. Local validation was limited to x86-64 with placeholders for unselected payloads (not shipped). Other targets need cross-compilers and QEMU, as in stage 11.5.

Scope: exactly one trailing RELOCATION section, one FLAT couple16/entry, INIT_DATA -> CONSTANT_DATA absolute pointer only, nonnegative in-section addend. No instruction patching, multiple relocations, other formats, import/export, or exhaustive malformed-input testing yet. Runtime header excludes relocation metadata. The source file remains unchanged.

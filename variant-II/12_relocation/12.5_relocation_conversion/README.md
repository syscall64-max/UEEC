# UEEC Variant II 12.5 — Relocation conversion

From 12_relocation run `make test` and `make sanitize`. Requires the same 12 toolchains and QEMU runners as 12.4. `make test` generates real payloads and writes build/integration-report.json; build/fixtures/conversion-report.json contains per-conversion size and elapsed time measurements (single wall-clock sample, not a benchmark). Loader is unchanged from 12.4.

Standalone: `python3 convert.py input.ueec output.ueec --format b4k32` (destination must not exist). Options: flat, b4k16, b4k32, b4k64, bn16, bn32, bn64; --block-n defaults to 24. Uniform SH16/32/64, both metadata byte orders, Couple16. Converter preserves ordered (couple, offset, type) records, other sections and relocation padding; updates relocation section sizes. Rejects unrepresentable offsets/counts and malformed structural records. It is not a complete semantic validator of arbitrary relocation targets: the Loader retains that responsibility. Currently rejects padded HEADER and trailing bytes, mixed SH formats and unknown relocation representations. BLOCK_N grouping is a converter choice; no N field is introduced. Round-trip equality is semantic, not necessarily byte-for-byte. No change to original format definitions.

42 directed small-fixture conversions and 30 directed large-fixture conversions per SH/endian combination, 432 successful conversions and round trips total. 36 large-to-FLAT conversions rejected. One value family (42) is used, with ISA-dependent payload variants as before. Every converted file is run in four modes on 12 architectures: 20,736 positive executions, 1,008 inherited Loader rejection cases. Each positive execution runs 3 load cycles and 6 native calls. SHA-256 checked before and after execution. No separate relocation latency benchmark; converter timing only.

Local x86-64 tests use real x86-64 payload and inherited placeholders for nonselected architectures; no build data included in archive. Full cross-architecture test pending.

# UEEC VM — ორი პროგრამა ერთ კონტეინერში

ეს ეტაპი ძველი ერთნოდიანი UEF ფორმატის VM-ს მოქმედ მრავალნოდიან UEEC
ფორმატთან აერთიანებს. კონტეინერის ფორმატი უცვლელია: `_GM`, იგივე ნოდები,
მიბმები, სახელები და SH16/SH32/SH64 სექციების აღწერები.

საქაღალდე `16_ueec_vm` დაამატე არსებულ პროექტს. წინა ეტაპების შეცვლა არ სჭირდება.
საჭიროა Linux, C კომპილატორი, Make და Python 3. NASM აუცილებელი არ არის.

```sh
cd 16_ueec_vm
make
make list
make run
```

ორივე ნოდში `machine_type=2` (VM) და `machine=0` (UEEC VM).

* `hello` — საერთო IDATA-დან კითხულობს 1234-ს და ბეჭდავს ტექსტს.
* `stack` — ასრულებს შენს თავდაპირველ PUSH/POP/CALL/RET მაგალითს.

შერჩევა სახელით ან ნოდის ინდექსით:

```sh
./build/ueec-vm --node hello build/programs.ueec
./build/ueec-vm --node stack build/programs.ueec
./build/ueec-vm --node 0 build/programs.ueec
./build/ueec-vm --node 1 build/programs.ueec
```

ერთ ფაილში არის 2 პროგრამის ნოდი, 2 სხვადასხვა CODE სექცია და ერთი ფიზიკური
INIT_DATA სექცია, რომელსაც ორივე ნოდი იყენებს. HEADER საერთო და არაპირდაპირია.
კომპაქტური ფაილის ზომაა 262 ბაიტი.

შენარჩუნებულია 16 რეგისტრი, 16-ბიტიანი მეხსიერების უჯრედები, 4096-ბაიტიანი
სტეკი, BP/SP და სტეკისგან განცალკევებული CALL-ის ჩარჩოები, სიღრმის ლიმიტით 512.
რვაბიტიანი FORMAT ამოღებულია. დარჩენილია FORMAT16/32/64, უცვლელი ნომრებით
1/2/3. ოპერანდებისთვის კოდი 0 რეზერვშია; SYSCALL-ის ფიქსირებული ფორმატი=0
რვაბიტიან ოპერაციას არ ნიშნავს. ძველი FORMAT8 ბაიტკოდი უარყოფილია.

`stack` ნოდში ძველი რვაბიტიანი ოპერაციები 16-ბიტიანით შეიცვალა.
შედეგები უცვლელია; CODE-ის ზომა 102-დან 104 ბაიტამდე გაიზარდა. ახალი წყაროა
`examples/stack16.asm` — უშუალოდ ბაიტკოდი, ძველი UEF კონტეინერის გარეშე.
ტექსტის გამოსატანად დამატებულია VM-ის სერვისი `SYSCALL 1`.

```sh
./build/ueec-vm --node stack --load-mode monolithic build/programs.ueec
./build/ueec-vm --node stack --load-mode scattered build/programs.ueec
./build/ueec-vm --node stack --load-mode hybrid build/programs.ueec
./build/ueec-vm --node stack --trace build/programs.ueec
./build/ueec-info build/programs.ueec
make test
make sanitize
```

შემოწმებულია 162 შემთხვევა ჩვეულებრივი გაშვებით და იგივე 162 ASan/UBSan-ით,
x86-64 გარემოში. მატრიცა მოიცავს ორივე პროგრამას, SH16/SH32/SH64-ს, მეტამონაცემების
ორივე ბაიტურ მიმდევრობას, კომპაქტურ/4096-ბაიტიან გრანულაციასა და ჩატვირთვის
ყველა არჩევანს. LeakSanitizer ამ გარემოში ვერ მუშაობს და გამორთულია.

ამ ეტაპზე ერთ ჯერზე ერთი პროგრამა ეშვება; ორივეს ერთდროული მუშაობა და საერთო
ცვლადი ოპერატიული მეხსიერება არ არის რეალიზებული. ინტეგრირებული არ არის
RELOCATION/EXPORT/IMPORT, HEAP, ენის კომპილატორი ან ახალი ენის ინტერპრეტატორი.
ბაიტკოდისთვის გამოიყენება მხოლოდ CODE და სურვილისამებრ INIT_DATA.

ძველი ერთნოდიანი ფორმატი შენახულია მხოლოდ `reference/` მაგალითებში შესადარებლად.
ახალ `programs.ueec` ფაილში ძველი UEF ჰედერი არ იდება. სრული ტექნიკური აღწერა,
შეცვლილი ქცევების ჩამონათვალი და ტესტების ფარგლები მოცემულია `README.md`-ში.

შემდგომი მიმართულებებია FORMAT128 და SIMD: ერთი ვექტორული VM ბრძანება
მასპინძელი პროცესორის შესაბამისი ინსტრუქციით შესრულდება, თუ ხელმისაწვდომია;
სხვა შემთხვევაში იგივე ოპერაცია სკალარული ციკლით შესრულდება. ორივე გზის
სემანტიკა ერთნაირი უნდა იყოს. ეს შესაძლებლობები ჯერ არ არის რეალიზებული.

ავტორის x86-64 გარემოში NASM-ით 165 შემოწმება წარმატებით დასრულდა ჩვეულებრივად,
ASan/UBSan-ით და დამატებით LeakSanitizer-ის ჩართვითაც. დამატებითი სამი შემთხვევა
NASM-ის გამომავალ ბაიტებთან შედარებაა. ავტორის მოწოდებული ამონარიდი ცალკეა
შენახული `evidence/user-validation-20261116.txt`-ში; ეს შედეგები გამოყოფილია
ლოკალურად გამეორებული 162 შემოწმებისგან.

# UEEC Variant II — 12.3 Instruction Relocation

Run `make test` and `make sanitize` from `12_relocation`. The full cross toolchain and QEMU runners from 12.2 are required. The report is `build/integration-report.json` inside this stage.

This experiment preserves the 12.2 FLAT Couple16 layout and ABS types 0/1. It provisionally assigns type 2 to an ISA-specific unconditional PC-relative branch. The instruction immediate encodes an unsigned byte offset from the source CODE section base; the loader translates it into the ISA's displacement relative to the branch PC. Only same-CODE-section branches are supported. The fixture jumps to offset 8, relocates the branch there to offset 32, then executes the existing data relocation payload. The eight ABS records remain. The loader checks code bytes outside the patched instruction are unchanged, checks opcode and bounds, rejects overlaps, and clears the instruction cache after patching before RX protection. This is an experimental type assignment, not a finalized format standard. No general ELF relocation conversion, cross-section branch, split address materialization or arbitrary instruction boundary validation is implemented.

Per architecture: 72 positive cases, 24 rejections, 216 load cycles and 432 calls. Native x86-64 ordinary and ASan/UBSan passed using dummy unselected payloads locally; no dummy payloads are distributed. Clang assembled and extracted relocation-free payloads for i686, ARM32, AArch64, RV32, RV64, PPC32, PPC64 and S390X; these were not executed locally. SPARC32/64 and LoongArch64 still require assembly and execution verification in the target environment.

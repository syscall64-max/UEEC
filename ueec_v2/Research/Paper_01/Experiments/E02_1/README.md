# UEEC Paper 01 / E02.1
Single x86-64 node, process termination status 0, no CRT, imports, exports or relocations. Linux uses syscall 60; PE uses NtTerminateProcess on current-process pseudo-handle -1, syscall 0x2c (Windows 10 22H2 x64 reference; verify on target build). Source: https://github.com/j00ru/windows-syscalls and https://www.windowssyscalls.com/en/syscalls/nt-terminate-process . PE execution not tested; Linux execution tested using existing unchanged loader from UEEC-main.zip, UEEC-main/02_ueec_load/{ueec.h,ueec_load.c}. Not a test of Variant II.

Run on x86-64 Linux: `./run.sh` (requires clang, lld-link, GNU binutils, C compiler, Python 3). Windows PowerShell: `$p = Start-Process -FilePath (Resolve-Path .\fixtures\exit.exe) -Wait -PassThru; $p.ExitCode` and record OS build with `Get-ComputerInfo | Select WindowsVersion, OsBuildNumber, OsArchitecture`. Verify syscall number for target before running. No Windows runtime result claimed.

CSV: headers include all ELF header tables, PE DOS prefix and all PE headers before header padding, UEEC name table and mapping. ELF other section data includes symbol/string tables; gaps are residual unassigned bytes, not necessarily all zero padding. PE padding is header + section raw tail beyond virtual size in this fixture. These are ordinary linker outputs, not minima; UEEC is directly serialized, so toolchain choices are confounders. A separate compact ELF/PE comparison is required. Linux payload identical across UEEC and ELF. UEEC header uses one name (exit) and implicit HEADER membership. No public repo changes.

# E11 — Runtime Header
Linux x86-64, 4096-byte pages, C compiler and Python 3. Run ./run.sh. The suite reuses the E10 single-node and E03 shared-data multi-node fixtures and their respective experimental loaders. The original loader sources are retained; the only new change is a readback observer before execution. It checks runtime magic/version, host byte order, single node/name counts, selected node word, section format, all section types and sizes, aligned pointer table (including self pointer), name metadata, and first/last constant data bytes addressed via the pointer table. The driver verifies exit status, actual loading mode, independent size formula and source file SHA-256 before/after. 108 single-node + 666 multi-node combined checks. Each combined check includes one native execution. The observer is C code in the loader, not payload code reading the header. Only little-endian x86-64 fixtures; no new allocator, no performance measurements, no unchanged v2 loader validation. Runtime section_size here describes allocated page-rounded capacity; not a normative format rule. No repository modifications. Results are regenerated by run.sh. Original fixture provenance: E10 (E02.7) and E03, previously confirmed by user.

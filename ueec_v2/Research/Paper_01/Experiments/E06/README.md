# E06 — Section Padding Management
Run ./run.sh on Linux x86-64 with Python 3 and GCC/Clang. Uses unchanged E05 experimental loader. Six constant-data sizes, two metadata byte orders, two payload cases and eight sequential alignment operations (including repeated alignments) produce 192 transformations and 576 native executions. Six isolated width selection boundary tests do not allocate large memory. Each operation preserves typed payloads byte-for-byte including two trailing logical zeros, rebuilds header and zero padding, and checks exact restoration of the original compact file. Alignment applies to all four physical sections including HEADER and RELOCATION. The producer selects a single width for all headers, accounting for the host page-rounded runtime representation to avoid the E04 loader limitation; this is a host-specific policy, not a wire-format requirement. The compact baseline for large sections therefore uses SH32 even when SH16 can encode the on-disk size. SH64 is only tested by isolated width selection, not executed here. Fixture-specific converter only; no arbitrary padding preservation, UNINIT_DATA, ELF comparison or performance tests in this package. Each transformation executes in all three loader modes. Repeated alignments overwrite equivalent fixture names; CSV counts are operations, not distinct files. No official specification change.

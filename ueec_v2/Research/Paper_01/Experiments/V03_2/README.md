# V03.2 — Selective padding comparison

Run `./run.sh` on Linux x86-64 with 4096-byte pages, Python 3 and a GCC-compatible C compiler. Original 12.6 load.c and ueec.h are copied unchanged from V03; SHA-256 verified before and after. A separate harness invokes original loader internals, with section indices adapted to the new fixture order. No loader changes.

Four constant payload lengths (16, 511, 4095, 61441), two controls (exit 40/41), eight alignment steps (1,16,64,512,4096,65536,64,1). Same native function bytes and data as V03; UEEC order is HEADER, CODE, CONSTANT_DATA, INIT_DATA, UNINIT_DATA, temporary RELOCATION. ELF uses a 34-byte startup stub and prelinked pointer, three non-overlapping PT_LOAD protection groups RX/R/RW, no section table. ELF flags and page separation are checked structurally, not with live permission probes. Original UEEC loader implements runtime protections as tested in V02.

UEEC selective aligns file offsets of CODE, CONSTANT_DATA and INIT_DATA only, by extending the preceding section; it does not round the last section or temporary relocation. UEEC packed uses alignment 1 regardless of requested alignment and is a separate reference policy, NOT an equal-file-alignment comparison. ELF split aligns the entry stub to the requested alignment, constant and initialized data starts to max(page size, requested alignment). Thus payload offsets and loading mechanisms are not identical: the UEEC function is called by the loader, ELF function follows a startup stub. The ELF header is mapped within the RX segment while UEEC runtime header has R protection. Payload protection groups are comparable but overall layouts are not identical. UEEC BSS stores 16 physical zeros, ELF uses p_memsz > p_filesz. The width selector accounts for runtime page rounding. Padding can increase runtime allocation because the original loader allocates section_size rounded to pages. No generic ELF rewriter, physical disk usage, RSS or performance measurement. ELF image size is calculated from PT_LOAD page coverage, UEEC from loader allocation sizes. These exclude loader and input-file mappings.

Expected counts: 192 layout checks (64 each for UEEC selective, UEEC packed and ELF split); 448 executions (192 each UEEC policy, 64 ELF); total 640. Counts include repeat alignment steps; not unique files. Each execution checks result and unchanged input bytes. Returning to alignment 1 restores initial bytes. Results in results.csv. Only x86-64 little-endian metadata tested.

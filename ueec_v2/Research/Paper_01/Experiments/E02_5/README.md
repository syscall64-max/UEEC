# E02.5 — CODE + UNINIT_DATA
Linux x86-64; requires GNU binutils, C compiler, Python 3. Run ./run.sh.
The same 66-byte instruction sequence (except size immediate and address operand) checks every requested byte is zero, writes 42 at the beginning and 1 at the end, reads both and exits 43. Sizes: 16, 256, 4096, 32768 bytes. Physical UEEC fixtures deliberately contain A5 bytes in the unused on-disk area to check that they are not copied into runtime UNINIT_DATA. All data_size fields for UNINIT_DATA are zero.
Physical uses inherited v1 section_size-based file offsets. NOBITS is a test-only alternative enabled by UEEC_EXPERIMENT_NOBITS=1; offsets and extent checks omit UNINIT_DATA with data_size=0. This is not a standardized wire format or an unmodified v2 implementation; the environment flag is external to the file and does not identify a new wire version. The narrow relocation bridge from E02.4 is adapted to UNINIT_DATA; relocation remains resident. Original first-generation loader and cumulative patch retained. Trusted generated fixtures only. ELF single is RWX, split RX/RW; no independent permission probes. File sizes are logical byte lengths, not allocated disk blocks; exclude loaders. No memory consumption, timing, or Windows/macOS claims.
80 positive executions: 4 sizes x (2 ELF + 3 widths x 3 modes x 2 UEEC layouts). No general malformed-file or compatibility test suite. results.csv, execution.csv, test.log contain measured local results. Documentation/publication deferred.

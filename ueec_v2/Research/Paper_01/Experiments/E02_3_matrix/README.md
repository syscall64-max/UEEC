# E02.3 expanded matrix — preliminary integration experiment
Linux x86-64; requires gcc or clang, GNU binutils, Python 3. Run `./run.sh`.
The two datasets sum to 42 and 43. ELF single and split plus UEEC SH16/32/64 × monolithic/scattered/hybrid are tested. The 34-byte code differs only in its 8-byte address operand, resolved statically in ELF and at load time in UEEC. `results.csv` contains file sizes, `execution.csv` the execution matrix, `test.log` the console output.
Reference: UEEC-main.zip, 02_ueec_load/ueec_load.c and ueec.h. Original loader retained as reference/ueec_load.original.c. The modified loader adds a deliberately narrow test-only FLAT ABS64 bridge for the single relocation used by the fixtures, using v1 relocation indices excluding HEADER. It also checks runtime header address entries. This is NOT the unmodified v2 loader or a general relocation implementation. RELOCATION stays resident in this bridge, unlike the previous E02.3 v1 03_reloc loader. The reported regions are the runtime image regions only, not total mmap calls. No performance or general relocation claims follow. Only trusted generated fixtures should be used. Full v2 integration remains outstanding. ELF split uses a 4096-byte file offset; it is not a minimum. File size excludes the UEEC loader. No Windows/macOS testing.

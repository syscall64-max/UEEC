# Paper 01 — E02.7 Structural scalability
Linux x86-64, run ./run.sh (C compiler and Python 3). Six UEEC section counts (including HEADER and, when present, RELOCATION), three widths, three loading modes, two cases. 36 ELF executions and 108 UEEC executions. Data sections have 16 bytes each; first byte contributes to exit status modulo 256. The no-data case uses a 12-byte exit program with different immediate values for base/control; other cases change only one data byte. The generator explicitly emits machine code and patches ABS64 addresses in ELF; UEEC uses experimental v1 FLAT records. The original v1 loader is retained; experiment.patch captures changes. The fixture-specific relocation bridge is not a general decoder. No NOBITS sections in this experiment. ELF variants: one RX segment with no section table; one RX segment with unnamed section headers (null entry, code, each data section, no section-name string table); separate RX and R segments on 4096-byte boundaries, no section table. Different protection granularity and fixed ELF addresses versus runtime UEEC relocation are limitations. Split layout is not claimed minimal. Loader overhead excluded; no timing or protection fault probes. No repository or specification changes. results.csv records file sizes for base case, execution.csv all runs; test.log records local execution. No-data split and compact are identical, and repeated scenarios are not distinct programs.

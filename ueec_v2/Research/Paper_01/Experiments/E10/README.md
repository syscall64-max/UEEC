# E10 — UEEC loading models
Linux x86-64, Python 3, C compiler. Run `./run.sh`. Inputs are the 36 UEEC fixtures from E02.7 (six section counts, two payload variants, three section-header widths). The experimental E02.7 loader is retained as `reference/ueec_load.previous.c`; the patch only adds observations and cleanup validation, not a new allocation policy.

For each fixture and each of three forced modes, execute once (direct exit syscall) and load without executing once, checking cleanup. The existing runtime address and relocation checks are retained. Additional checks: page alignment, containment in exactly one allocation region, no section overlap, contiguous addresses for monolithic and hybrid payload sections, matching total region and section allocation lengths, and actual permissions in /proc/self/maps. For no-run cases, mincore must report ENOMEM on every previously allocated image page after release. Input SHA-256 is compared before/after each fixture's tests. The data-byte total includes the runtime header and resident relocation metadata; unused capacity is allocated bytes minus that total. No inference about RSS, physical memory, VMA count or speed is made. Region counts exclude the file mapping and ancillary libc allocations. Permissions are inspected, not fault-probed. Direct exit bypasses explicit cleanup, so cleanup is checked separately. No ELF comparison or unchanged second-generation loader validation in this stage. Only the fixed E02.7 fixtures are tested, not all possible UEEC files.

Expected on 4096-byte pages: 108 native runs and 108 load/release tests, 216 total. CSVs record per-run and per-section metrics. A 32-section fixture allocates 131072 bytes in all modes. No timings are reported.

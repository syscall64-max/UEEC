# E02.4 — CODE + INIT_DATA (preliminary integration experiment)
Linux x86-64; requires a C compiler, GNU binutils, Python 3. Run `./run.sh`.
The payload reads the first initialized byte, adds 5, writes it, verifies the write, then sums all 16 initialized bytes and exits. Base/control initial sums 42/43 produce 47/48; failed read-back returns 255. All five format/layout variants use identical instructions apart from the absolute data address operand. ELF resolves it statically; UEEC resolves it at load time.
ELF single is intentionally RWX and is a size-only baseline, not permission-equivalent to UEEC. ELF split uses RX code and RW data with 4096-byte file offset, not an asserted minimum. UEEC uses RX CODE and RW INIT_DATA. No independent negative permission probes are performed here.
Reference: first-generation 02_ueec_load loader, inherited from E02.3 expanded matrix. Original loader retained in reference/ueec_load.original.c; experiment.patch records the narrow FLAT ABS64 bridge and runtime header checks, now restricted to INIT_DATA. Relocation section remains resident. Not an unmodified v2 loader or general relocation validation. Use only trusted fixtures. Runtime region counts exclude other process mappings. File sizes exclude loader. No performance or Windows/macOS claims.
results.csv records file sizes; execution.csv records execution results; test.log records output; environment.txt records local tools. Documentation and repository publication deferred.

# V03 — Padding management comparison

Run `./run.sh` on Linux x86-64, 4096-byte pages, with GCC-compatible C compiler and Python 3. `load.c` and `ueec.h` are unchanged from V02 / UEEC v2 12.6; their checksums are verified before and after. The separate C harness calls the original loader's internal functions, not its fixture-specific CLI. No modification to loader algorithms.

Four constant payload sizes (16, 511, 4095, 61441), two controls (return 40 or 41), eight sequential alignment steps (1,16,64,512,4096,65536,64,1). UEEC has HEADER, CODE, INIT_DATA, UNINIT_DATA, CONSTANT_DATA and temporary RELOCATION. The native function reads constant data (including the trailing meaningful zero) and the zero-initialized byte via the relocated pointer. The same function bytes are used in ELF, with a 34-byte startup stub and a prelinked absolute pointer. ELF uses fixed-address ET_EXEC, no dynamic linking or section table; compact has one RWX PT_LOAD, split has separate RX, R, RW PT_LOADs. Compact is not protection-equivalent. ELF p_filesz/p_memsz represent the initialized/uninitialized distinction; UEEC loader used here stores physical zero bytes for the uninitialized section.

Each UEEC transformation extracts logical payloads using data_size, rebuilds section sizes, selects a uniform SH width accounting for page-rounded runtime sizes, validates payload bytes and executes three modes. ELF transformations extract the same code/constant payloads from the preceding generated layout using known offsets, rebuild offsets, entry point, program headers and absolute pointers, and execute through the kernel. This is a controlled relayout generator, not a generic ELF editor or linker. Rebuilding alignment=1 reproduces initial bytes in each format. UEEC rounds all section sizes; ELF aligns payload start offsets (split requires at least a page boundary between protection groups). These policies are deliberately not identical. Neither is claimed to be the minimum possible file size. File size means logical byte length, not physical disk blocks. CSV padding excludes the entire physical UEEC UNINIT_DATA section (reported separately); ELF BSS is not stored. UEEC image_virtual_bytes is the sum of allocation sizes returned by the loader, excludes input mapping and loader process; ELF image_virtual_bytes is calculated from PT_LOAD page ranges, not measured RSS. No performance conclusion.

192 layout checks (64 per representation), 320 native executions (192 UEEC, 128 ELF). Expected total 512. Counts include repeated alignment steps, not unique binaries. Initial development run exposed incorrect local relocation indices in the new generator; fixed before successful run. No changes to original loader. Only little-endian x86-64 tested. No generic ELF transformations, shared-library ABI, or physical disk usage measured.

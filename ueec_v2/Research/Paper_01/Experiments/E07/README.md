# E07 — Relocation designs

Linux x86-64, Python 3 and a C compiler. Run `./run.sh`.

This experiment adapts the E06 experimental loader to decode seven first-generation relocation encodings, with the original 04_convert loader retained for reference. It supports one CODE <- CONSTANT_DATA pair (target=1, source=2), Couple16, ABS64, sorted nonoverlapping offsets, both metadata byte orders, and all three allocation modes. It is not a general v2 relocation engine. The Python generator selects section header width accounting for the current loader's runtime page alignment; relocation width is independent. Each native program dereferences every relocated pointer, using varying implicit addends; a control changes the source bytes. Return status is the sum modulo 256. The 10 workloads include dense, sparse and page-strided offsets. BLOCK_N uses a 1024-byte grouping in the main matrix; five grouping sizes are tested separately. Unrepresentable encodings are excluded from execution and explicitly marked. Conversion checks apply to relocation blobs, not entire arbitrary UEEC containers. Malformed blobs are tested for trailing bytes, wrong pair, wrong type and out-of-range block base. A rejected private image is not executed.

ELF comparison is structural only: REL64=16 bytes/entry, RELA64=24 bytes/entry, RELR64 uses address/bitmap words of 8 bytes. RELR encode/decode is checked for the same aligned offsets; its semantics are relative to the object load bias, not independently positioned UEEC sections. These numbers exclude ELF section headers, dynamic tags, symbols and other supporting structures. No ELF loader execution or timing is claimed. See https://gabi.xinuos.com/v42/elf/06-reloc.html .

Expected with 4096-byte pages: 756 native executions, 882 conversion checks (72 expected unrepresentable destinations), 240 malformed relocation rejections, 10 RELR encoding/decoding checks, 150 BLOCK_N parameter checks (9 unrepresentable), total 2038. Counts include repeats and expected rejections; they are not unique executed programs. No official format or repository changes.

`results.csv` holds UEEC relocation and complete file sizes, `execution.csv` native runs, `conversion.csv` conversion checks, `rejections.csv` malformed-input tests, `elf_structural.csv` ELF payload sizes, `block_sizes.csv` parameter sweep. `experiment.patch` records the experimental loader changes.
